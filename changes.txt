Allow positive TWTS centroid positions in the PICMI frontend

The shared laser validator previously rejected centroid_y > 0 for every
laser. TWTS computes its manual delay as (focal_y - centroid_y) / (beta0*c),
so this prevented zero delay at a positive focal position.

- All implementation changes are confined to the PICMI TWTSLaser class.
  The shared validator and all backend laser models retain their original
  implementation; Gaussian, dispersive and plane-wave lasers are unchanged.
- TWTS overrides _validate_common_properties() to allow positive centroid
  positions. It explicitly retains the three checks for normalized
  polarization, normalized propagation and a positive propagation-y
  component. This duplicates those short checks to keep the fix local.
- TWTS returns pulse_init = 0.0 as an unused compatibility value for the
  unchanged backend model. Its template uses TDELAY and the switching
  window, not PULSE_INIT or RAMP_INIT, so this does not alter the TWTS field.
  Deriving pulse_init from a positive centroid would instead produce a
  negative value rejected by the backend.
- Documented the TWTS timing semantics and added regression tests for
  centroid-to-delay conversion, zero-delay template rendering with a
  switching window, and preservation of the other laser restrictions.

TWTS still uses its existing windowStart, windowEnd and windowLength
parameters. Allowing a positive centroid does not initialize fields inside
the domain: the switching window and propagation time determine how the
boundary-injected field develops. Other setup-migration limitations are
separate from the centroid change; the polarization fix is described below.

Correct the TWTS polarization axis (task 2)

The z component of TWTSLaser.polarization_direction now uses sin(alpha),
where alpha is polarizationAngle, instead of cos(alpha). In the transverse
basis for k=(0,cos(phi),sin(phi)), the corrected direction is
(cos(alpha), -sin(alpha)*sin(phi), sin(alpha)*cos(phi)). It is a unit vector
orthogonal to k, including at the reference polarization angles. This is a
local correction to TWTSLaser; no shared validator or other laser changes
were needed. The scalar polarization angles and amplitudes sent to the C++
TWTS field functors are unchanged.

Expose the composite particle pusher (task 3)

Species.picongpu_composite_pusher option. The names follow Species.method.
The first pusher is active before switch_step and the second from that step
onwards. The switch is an absolute, strict integer in the uint32 range;
zero and steps beyond max_steps are supported. Omit method or set it to

Keep field interpolation consistent with species shape (task 4)

The species template previously used the global UsedField2Particle alias,
which selects TSC in the default species.param even when a species requests
cubic/PQS. It now defines one ParticleShape_species_<name> alias per species
and uses it in both the shape flag and
FieldToParticleInterpolation<..., AssignedTrilinearInterpolation>. Different
species can therefore gather fields with different shapes. No global alias
or new PICMI parameter is needed. Omitted/None species shapes remain TSC.
Current deposition still uses UsedParticleCurrentSolver and is task 5.

and no cached shapeArray interface. Backend species validation now rejects it
with a clear error, including PICMI conversion of other:counter, rather than
rendering an incompatible field interpolation. The enum remains available;
the restriction applies to using Counter as a species' interpolation shape.
